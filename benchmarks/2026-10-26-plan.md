## Benchmark Plan — 2026-10-26

### Selected Experiments (rank by expected ROI)

#### [1]. vLLM PCP & Steady-State PP Latency Profiling — vLLM (Latest Main)
**Hypothesis**: The new `bench forward` support for Prefill Context Parallelism (PCP) and Steady-State Pipeline Parallelism (PP) allows us to accurately isolate inter-node latency overheads on the 10GbE link. We expect to see that without PCP, the 2-node setup suffers from significant "straggler" effects due to uneven context lengths across GPUs. With PCP, latency variance should decrease, and total TTFT should improve for long-context workloads by reducing redundant prefill computations.

**Setup**:
  - Model: Meta-Llama-3-70B-Instruct (Fits in 128GB node with FP8/INT8 quantization or careful CPU offload; we will use full FP16/BF16 with KV cache offloading to CPU RAM if necessary, but primarily targeting GPU memory pressure).
  - Framework version: `vllm/vllm:nightly` (ensure latest main branch, commit date post 2026-10-20).
  - Node config: Both nodes (spark-01, spark-02).
  - Parallelism: TP=2 (Tensor Parallelism across nodes), PP=1 (Baseline) vs. PP=2 (if supported by model size) / PCP enabled.
  - Note: Since 70B is tight for 128GB per node in FP16 without CPU offload, we will use `--gpu-memory-utilization 0.9` and rely on the new KV offload cursor fix to prevent stalls during high preemption.
