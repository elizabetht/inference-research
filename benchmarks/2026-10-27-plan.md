## Benchmark Plan — 2026-10-27

### Selected Experiments (rank by expected ROI)

#### [1]. Kimi-K3 MLA KV-Balanced FP8 Decode — vLLM
**Hypothesis**: The Kimi-K3 KV-Balanced MLA attention backend reduces KV cache fragmentation and padding waste in variable-length agentic loops. By splitting KV cache per-request, we expect a ~15-20% improvement in decode throughput (tokens/s) and reduced Time-To-First-Token (TTFT) variance compared to the standard MLA implementation, especially under high concurrency.
**Setup**:
  - Model: Kimi-K3 (Assumed ~128B parameters, fits in unified memory of 1 node or TP=2)
  - Framework version: vLLM `main` (post-2026-10-27 PR merge) or specific commit hash implementing `KIMI_K3_KV_BALANCED_MLA`
  - Node config: Both nodes (spark-01, spark-02) to handle model size; TP=2 across nodes.
  - Parallelism: TP=2 (Tensor Parallelism), PP=1 (Pipeline Parallelism), GQA enabled.
**Benchmark script**:
```bash
#!/bin/bash
# Run on spark-01 and spark-02 simultaneously via SSH or Slurm
# Assumes vLLM installed in ~/inference-bench-env

source ~/inference-bench-env/bin/activate

# Environment variables for NCCL and Unified Memory
export NCCL_IB_DISABLE=0
export NCCL_DEBUG=WARN
export NCCL_ASYNC_ERROR_HANDLING=1
export PYTHONPATH=/path/to/vllm:$PYTHONPATH

# Run vLLM server with Kimi-K3 KV-Balanced MLA
python -m vllm.entrypoints.api_server \
    --model "Kimi-K3" \
    --tensor-parallel-size 2 \
    --distributed-executor-backend mpi \
    --attention-backend KIMI_K3_KV_BALANCED_MLA \
    --port 8000 \
    --host 0.0.0.0 \
    --disable-log-requests

# pip install vllm[bench]
python -m vllm.benchmarks.benchmark_throughput \
