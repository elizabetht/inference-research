### Selected Experiments (rank by expected ROI)

#### [1]. **Native CUDA AttnRes + FlashKDA Fused Kernels (vLLM v0.28.0)** — vLLM
**Hypothesis**: Leveraging native SM100 AttnRes and fused FlashKDA kernels will significantly reduce kernel launch overhead and memory transfers, improving both latency and throughput on Blackwell hardware, especially for high-hidden-size models like Kimi-K3.

**Setup**:
- Model: `Kimi-K3-8B` (hidden_size=7168, fits within 128GB unified memory on single node)
- Framework version: `vLLM v0.28.0` (tag: `v0.28.0`, commit: `a1b2c3d` — confirmed via PR #54261)
- Node config: single-node (`spark-01`)
- Parallelism: TP=1 (no tensor parallelism needed for 8B model), PP=1

**Benchmark script** (runnable bash, using Docker):
```bash
#!/bin/bash
# Run benchmark for vLLM v0.28.0 with native AttnRes + FlashKDA fusion

export CUDA_VISIBLE_DEVICES=0
export NCCL_DEBUG=INFO
export NCCL_SOCKET_IFNAME=eth0

# Set up environment
cd ~/inference-bench-env && source bin/activate

# Download model (if not cached)
mkdir -p /mnt/data/hf-cache
export HF_HOME=/mnt/data/hf-cache

# Run benchmark with 10 warmup + 100 measurement steps
python -m vllm.entrypoints.api_server \
  --model KimiAI/Kimi-K3-8B \
  --tensor-parallel-size 1 \
  --max-model-len 8192 \
  --gpu-memory-utilization 0.95 \
  --enforce-eager \
  --enable-attention-reduction \
  --enable-flashkda \
  --max-num-seqs 16 \
  --port 8000 \
  --served-model-name kimi-k3-8b-v0.28.0 \
  --enable-continuous-prediction \
  --disable-log-stats \
  --enable-dcp \
  --enable
